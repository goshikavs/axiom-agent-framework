# Evidence-verification benchmark

Compares four **independent** revalidation strategies on seeded graphs. This is not a claim that Goshikq detects unregistered dependencies, and it is not an end-to-end agent-runtime benchmark.

## Strategies

| Id | Code name | Behavior |
|---|---|---|
| A | `none` | Never revalidate. Predicted set is always empty. |
| B | `full_declared` | If any registered resource change hits, recheck **every** declared decision, action, and approval. |
| C | `conventional_prewrite` | Immediately before a write, compare versions of resources the **action node** declared (`resource_id`). No graph walk. Decisions and approvals are not selected. |
| D | `selective` | Goshikq `compute_impact` on the **declared** graph only. |

These are four functions in `crates/goshikq-core/src/baselines.rs`. Unit tests fail if they collapse to the same output on a fixture where they must differ.

`tests/perf/bench_evidence.py` is a live refund-run latency harness. It does **not** implement A–D.

## Ground truth

Built in `crates/goshikq-bench/src/ground_truth.rs`:

1. Take declared edges plus **hidden** edges (true dependencies never registered).
2. BFS from nodes whose `resource_id` hit the change.
3. Collect decision / action / approval descendants.

This walk does not call `compute_impact`. Hidden edges are withheld from every strategy, so recall of D is expected to be **less than 1** on `hidden_dependency` families. That is the measurement, not a product defect claim of “we catch unknown deps.”

## Scenario families

Generated by `crates/goshikq-bench/src/generate.rs` for sizes 10, 100, 1_000, 10_000 (evidence-node counts; decisions/actions/approvals scale with size):

- unrelated change (isolated resource)
- multiple simultaneous / concurrent changes
- deleted evidence
- inaccessible evidence
- missing versions
- approval delay (metadata only; no sleep)
- external-operation delay (metadata only; no sleep)
- duplicate change events
- cyclic graph attempt
- missing registered dependencies
- hidden dependency

Fixed `--seed` plus `(size, family, trial)` mixing makes generation deterministic.

## Metrics

Against ground truth:

- impact **recall** and **precision** (union of decisions, actions, approvals)
- **missed critical actions** (true-graph actions not blocked)
- **false-positive revalidation** (predicted nodes not in ground truth)
- **incorrect-action rate** (trial-level: 1 if any critical action missed)
- **verification workload** (count of predicted nodes)
- **latency** (wall-clock of the strategy function, nanoseconds)

**Not measured here (labeled unknown / N/A):**

- database overhead (in-process graphs; no PostgreSQL)
- model API cost per verified outcome (no LLM)
- CPU time (wall-clock only)
- end-to-end agent/tool I/O

Confidence intervals are normal-approximation 95% intervals across trials when `n > 1`. They are not bootstrap intervals.

## Reproduction

Windows (this repository’s MSVC wrapper):

```powershell
scripts/with-msvc.ps1 cargo +stable-x86_64-pc-windows-msvc run -p goshikq-bench --release -- --sizes 10,100,1000,10000 --trials 10 --seed 42 --out benchmarks/evidence/results.json
```

Linux/macOS CI-style smoke:

```bash
cargo run -p goshikq-bench -- --sizes 10,100 --trials 3 --seed 42 --out /tmp/evidence-bench.json
```

The unlabeled “recall” in v0.3.1 mixed four questions. They are now separate fields in `TrialMetrics` (see `docs/milestones/v0.3.2-report.md`). Full-declared true-impact recall of 1.0 is `trivial_full_selection` when hidden edges land on existing declared node ids.

Policies E `selective_plus_prewrite` and F `strict_contract` were added without changing A–D outputs. Reproduction for the labeled run:

```text
.\target\release\goshikq-bench.exe --sizes 10,100,1000,10000 --trials 10 --seed 42 --out benchmarks/evidence/results-v0.3.2.json
```

## Results (this host, 2026-10-29 UTC)

Command:

```text
cargo +stable-x86_64-pc-windows-msvc build --release --package goshikq-bench
.\target\release\goshikq-bench.exe --sizes 10,100,1000,10000 --trials 10 --seed 42 --out benchmarks/evidence/results.json
```

Host (from `benchmarks/evidence/summary.json`): Windows x86_64 process, Snapdragon(R) X 12-core X1E80100 @ 3.40 GHz, 12-way, rustc 1.98.0 (88d9e12ae 2026-08-18), Goshikq 0.1.0-alpha. RSS after: 38.3 MiB; peak working set 44.3 MiB. 48 cells × 10 trials = 480 observations per strategy.

### Overall (all sizes and families)

| Strategy | Recall | Precision | Incorrect-action rate | Mean workload | Mean latency |
|---|---|---|---|---|---|
| A none | 0.167 [0.133, 0.200] | 1.000 | 0.833 | 0 | 0.33 µs |
| B full_declared | 1.000 | 0.249 [0.217, 0.280] | 0.000 | 2228 | 384 µs |
| C conventional_prewrite | 0.302 [0.274, 0.330] | 1.000 | 0.833 | 0.96 | 106 µs |
| D selective | 0.645 [0.628, 0.661] | 1.000 | 0.785 | 3.65 | 82 µs |

Intervals are 95% normal-approximation CIs. Full tables: `benchmarks/evidence/summary.json`. Raw trials: `benchmarks/evidence/results.json`.

|---|---|---|---|---|---|---|

| 100 | 0.617 | 3.9 | 79.8 | 0.162 | 20 µs | 20 µs |

### Interpretation

- D’s precision is 1.0 because the declared graph is a subgraph of the true graph: every node D selects is truly affected. D’s recall is below 1 because hidden edges are withheld. **This does not measure detection of unknown dependencies.**
- B’s recall is 1.0 because hidden edges land on node ids that already exist; rechecking every declared node covers them and floods unrelated nodes (precision falls as graphs grow).
- C never selects decisions. It only version-checks action-declared resources.
- A never revalidates. Overall recall 0.167 is the two empty-truth families out of twelve (vacuous recall 1.0), not “it found 17% of dependents.”
- Database overhead is N/A. Model cost is unknown. These latencies are in-process graph walks, not Studio or PostgreSQL.
