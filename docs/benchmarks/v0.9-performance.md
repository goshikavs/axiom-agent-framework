# v0.9 performance

Workload: `python tests/perf/bench_v09.py` against a live `axiom-server`. Health probes isolate HTTP overhead. Echo workflows use native TOOL handlers (no model).

Results from this host (Windows, 12 logical CPUs), `python tests/perf/bench_v09.py` against `127.0.0.1:7400`:

| Probe | n | p50 | p95 | p99 |
|---|---|---|---|---|
| `/health` ms | 50 | 1.00 | 1.95 | 2.39 |
| Echo workflow conc=1 | 1 | 182 ms | 182 ms | 182 ms |
| Echo workflow conc=10 | 10 | 1046 ms | 1174 ms | 1174 ms |

Throughput at concurrency 10: ~8.3 workflows/s (native echo, no model). Concurrency 100 was not run. These numbers are not a product claim.

## What is measured

- p50/p95/p99 of `/health`
- Echo-workflow wall time at concurrency 1 and 10 (100 is opt-in via `AXIOM_BENCH_CONCURRENCY=1,10,100`)
- Error counts and throughput

## What is not measured here

- Paid model latency
- PostgreSQL storage latency as a separate histogram (use `runtime/metrics` + your APM)
- Cross-region network

## Hardware

Record `os` and `cpu_count` from the JSON output. This host is Windows; Linux/macOS numbers must come from those runners.
