## 9. Benchmarks

- 1 tool call, full create+poll+verify: **206 ms** (run `01a1889c-9be0-73c0-b6b8-c5f23c1d5228`)

These include HTTP long-poll, snapshots, and verification. They are not LLM latency and not a Bun-vs-Python speed claim. Dominant cost is the run lifecycle over localhost HTTP, not TypeScript execution.

## 10. Security findings

- MCP descriptions cannot add tools, flip effect, or skip approval.
- Remote MCP HTTP requires Authorization and an endpoint allowlist (https or loopback).
- OTLP + REST with two API keys: project B cannot read project A’s run; mismatched `X-Goshikq-Project-Id` is 403.
- Secrets in MCP error details matching password/token/authorization are redacted.
- Non-idempotent MCP tools use `maxAttempts: 1` unless marked idempotent by Goshikq policy.

## 11. Known limitations

- TypeScript SDK does not resume arbitrary closures after a crash; only persisted runtime state + idempotency keys.
- MCP client implements documented JSON-RPC 2024-11-05 (stdio Content-Length, HTTP POST). It is not a wrapper around `@modelcontextprotocol/sdk`.
- MCP HTTP remote transport is implemented and unit-constrained; no third-party hosted MCP server was used.
- OpenAI Agents `Runner.run` was not completed offline on 0.24.0; processor + ingest were.
- `target/debug/goshikq-server.exe` could not be overwritten while the v0.5 process held the file; the v0.6 binary was built to `target/x86_64-pc-windows-msvc/debug/`. Isolation and CLI used that path. Restart the loopback server from the new binary to pick up `/api/v1/api-keys` on port 7400.
- Replay reconstructs only recorded `state.snapshot` / `state.changed` events. Missing steps show that limitation. Latest GET `/state` is labeled current.
